# AI寻物六因子重排

版本：semantic_six_factor_v1。

## 实现

先按校区、公开审核与可用状态过滤，再进行真实本地向量召回；固定取语义相似度大于0的前50条重排，最后取展示条数。展示条数不改变召回池。兼容未提供草稿的纯语义调用，用于前后对比。

复用既有 MatchingEngine.compute_factors 的类别层级、颜色集合、品牌词典别称、地点层级和时间容差/衰减规则，文本因子替换为本地语义余弦值。读取当前已发布算法配置的六因子权重、时间参数与别称；无配置时用引擎默认值。默认权重：语义0.50、类别0.15、地点0.12、时间0.10、颜色0.08、品牌0.05。

基础分 = 已知因子的加权和 / 已知因子权重和。未知信息不记0分，不产生冲突惩罚。类别提示只做词典最长、唯一匹配；无法识别或有歧义时按未知处理，支持类别词典中的别称。

类别叶子明确不同（包括耳机和手机即使属于同一上级类别）再乘0.25；颜色不相交乘0.55；品牌明确不同乘0.65；拾取时间早于遗失时间且超过既有容差乘0.35。多项冲突连乘。地点仍按原规则参与基础分，不增加额外惩罚。

这些乘数是明确记录的初始工程策略，未经过真实校园样本拟合或校准。分数只用于排序，不能解释为归属概率；尚未设置经验证的“正确物品”阈值。

## 公开边界

只从确认草稿和候选的公开类别、颜色、品牌、事件时间及公开地点层级取值。不调用包含受保护地点候选和坐标的 item_to_feature，不读取私密答案、认领资料或自由文本精确地点。所有解释只反映公开字段和缺失/冲突状态。

返回 ranking：版本、配置版本、原始语义值、基础分、覆盖度、有效权重、六因子值、缺失项、冲突项、惩罚乘数与最终排序分。前端可展开“查看排序依据”。

## 验证

`backend/manage.py verify_assistant_ranking` 使用本地真实向量模型、同一条合成耳机图的已保存观察与同一批演示记录，分别记录纯语义和重排前五名。结果见 artifacts/assistant-reranking-verification.json，不修改业务记录。

该次案例：纯语义首位为蓝色耳机盒，第四、第五位是手机；重排后前两位为黑色耳机，前五位均为耳机类。单例改善不代表总体准确率；下一步需在独立固定查询集上比较召回、排序、困难负例与耗时，避免针对演示案例调参。

前端41项测试、类型检查与生产构建通过；真实浏览器流程通过（19.1秒），检查黑色候选优先及排序依据展开，截图为 artifacts/local-ai-browser-demo.png。后端回归覆盖未知信息、颜色冲突、两种查询方向的时间冲突、类别歧义、较高语义相似度的错误类别、跨校区与未审核记录隔离。
