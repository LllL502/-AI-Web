# 01 产品需求与页面矩阵

## 1. 产品目标

“拾光 · CampusTrace”面向校园师生，提供遗失发布、拾获登记、智能匹配、隐私保护认领、预约交接、消息通知与运营管理的完整闭环。系统以“公开信息最小化、敏感线索分级可见、全过程可追溯”为基本原则。

## 2. 角色与权限边界

| 能力 | USER 普通用户 | STAFF 站点协调员 | ADMIN 系统管理员 |
|---|---:|---:|---:|
| 浏览已审核公开物品 | ✓ | ✓ | ✓ |
| 发布、编辑本人草稿/被驳回信息 | ✓ | ✓ | ✓ |
| 查看本人匹配、认领、会话、通知 | ✓ | ✓ | ✓ |
| 审核物品、处理本站认领与交接 | — | 本站 | 全部 |
| 查看私密线索 | 认领举证时受限 | 本站按需 | 按审计授权 |
| 用户、字典、算法配置、系统任务 | — | — | ✓ |
| 查看原始媒体 | 本人上传 | 本站按需 | 按审计授权 |

对象权限始终叠加站点范围与字段级序列化规则。仅隐藏按钮不构成授权，所有写接口必须在服务端再次校验。

## 3. 业务状态分离

- 审核状态：`DRAFT → PENDING → APPROVED / REJECTED`。
- 物品业务状态：`OPEN → RESERVED → RETURNED / CLOSED / EXPIRED`。
- 认领状态：`DRAFT → SUBMITTED → NEEDS_INFO / APPROVED → HANDOVER_PENDING → COMPLETED`，并允许从待处理节点进入 `REJECTED` 或 `CANCELLED`。
- 审核状态与物品状态不可互相替代。例如审核通过的物品仍可处于 `OPEN`、`RESERVED` 或 `RETURNED`。

## 5. 系统页面

登录、注册、找回密码、管理员登录、403、404、500、离线页不计入上述 39 个业务页面，但必须独立设计并完成路由守卫与恢复路径。

## 6. 非功能约束

- 应用与数据库进程仅监听 `127.0.0.1`：本地前端默认 `5173`、后端默认 `8000`，数据库使用项目级 MySQL 8.4；可选公网测试通过出站 HTTPS 隧道转发至独立的本地生产预览进程，不直接开放端口。
- 安装完成后，核心页面不依赖 CDN；字体、图标与模型资源均本地提供。
- 普通动效遵循 `prefers-reduced-motion`；WebGL 不可用时展示可操作的 2D 回退。
- 个人联系方式、精确地点和私密特征默认不进入公开接口；所有越权结果使用 403/404 策略避免枚举。
