# 公网启动连接修复（2026-10-10）

旧日志持续出现 QUIC timeout，旧脚本仅匹配 trycloudflare URL 就宣布上线，未确认隧道连接与业务健康。复用已有前端构建本身不是隧道连接失败的证据。此前后端健康检查失败但无异常日志，不能认定为性能优化直接导致进程退出。

启动修复：

- 隧道明确使用 `--protocol http2`，走 TCP 7844，避免本次 QUIC/UDP 连接失败路径。
- 先检查本地首页与同源 API 健康（包含数据库查询），再启动隧道。
- 等待 `Registered tunnel connection`，不把域名生成当作连接成功。
- 检查真实公网首页 HTTP 200 与健康接口 status=ok，成功后才保存和输出分享链接。
- 连接或公网验证失败时停止测试服务，不输出错误的可分享状态。

实际运行：停止旧测试进程后运行新版启动脚本，本地健康、HTTP/2 注册与公网首页/健康检查均通过；数据库文件保留。测试链接存储于 artifacts/logs/public-test-url.txt。运行在本机进程中，电脑断网、休眠或停止进程会导致不可访问。

注意：HTTP/2 仍需网络允许 TCP 7844；本次成功不是所有网络环境的保证。外网注册登录闭环本轮未重新运行。停止使用 scripts/stop-public-test.cmd，再启动使用 scripts/start-public-test.cmd；每次 Quick Tunnel 域名可能变化。
