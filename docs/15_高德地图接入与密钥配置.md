# 高德地图接入与密钥配置

## 申请步骤

1. 打开 [高德开放平台](https://lbs.amap.com/)，注册或登录开发者账号，按控制台要求完成认证。
2. 进入控制台的「应用管理 → 我的应用」，创建应用，例如「拾光校园失物招领」。
3. 在应用下添加 Key，服务平台选择 **Web端（JS API）**，不是 Web服务、Android 或 iOS。
4. 保存生成的 Key 及配套安全密钥（securityJsCode）。不要在聊天、截图或 Git 仓库中公开安全密钥。
5. 如控制台要求域名白名单，按其格式填写实际访问域名；本地测试与公网测试分别配置。Cloudflare 临时域名重启后可能变化，需要同步更新。

申请入口：[高德控制台](https://console.amap.com/)。安全配置依据：[JS API 安全密钥官方说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。配额、认证和使用许可以账号控制台及平台现行规则为准。

## 本地填写位置

文件：`campustrace/backend/.env.amap`。填写等号右侧即可，不添加尖括号。

```dotenv
AMAP_WEB_KEY=你的Web端JSAPI的Key
AMAP_SECURITY_CODE=配套的安全密钥
```

此文件已加入 Git 忽略规则。浏览器可见的 JS API Key 不等同于服务器安全密钥；前端通过同源 `/_AMapService` 代理调用服务，安全密钥由后端注入，不能放进 `VITE_*` 配置。

填写后重新启动网站后端和公网测试启动脚本，刷新浏览器；顶部选择真实学校。已核实校区按学校与校区名称搜索；未核实校区按学校名称搜索，显示「校区资料待核实」，不把占位「主校区」当成真实校区。演示校区不启用真实地图。网站仍需要本机后端和隧道持续运行，地图 Key 不会让网站获得永久公网地址。

## 已实现的行为与边界

- 首页与校园地图页使用高德地图组件，随学校和校区切换重新加载。
- 校区名称查询返回候选地点；自动视角仅供查找，不代表校园中心经过人工核实，也不会回写为已核实校区坐标。
- 发布页支持手动选点或选择地图搜索结果：遗失线索可按可能性保存 0–5 个 GCJ-02 候选点，招领线索只保存 1 个已知拾获点；无建筑字典时只建立当前校区公共区域，不虚构图书馆、宿舍等地点。
- 精确坐标在公开物品 API 中脱敏，不把个人位置作为公开地图标记；不主动请求设备定位权限。
- 未配置、网络失败或查询失败时提供提示和重试，保留地点列表等核心业务。
- 代理限制上游地址和路径，限制请求长度、响应大小及超时，设置访问频率限制，不返回安全密钥。

地图底图不能替代校区边界、建筑字典和服务站核查。目前不做校区围栏校验，不保证用户选点一定在当前校区内；该功能需要后续补充真实边界数据。接入在线地图后，地图能力需要外部网络，不再属于完全离线资源。

## 常见问题

- 仍显示未配置：检查两个配置项是否均填写，并重启后端。
- Key 无效或鉴权失败：检查服务平台类型、Key 与安全密钥是否属于同一应用配置、当前域名是否被允许。
- 有底图但没有学校搜索结果：检查 `/_AMapService/v3/place/text` 请求、服务配额和代理网络；也可更换完整校区名称重新搜索。
- 公网出现 502：先检查本地网站与 Cloudflare 隧道是否运行；这与地图密钥是不同问题。
- 学校匹配到其他城市：候选结果需要人工选择，不应直接保存成权威校区资料。
