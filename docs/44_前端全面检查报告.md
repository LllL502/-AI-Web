# 前端检查报告

本轮结论：页面能加载、构建能通过，但仍有影响搜索、发布类型、会话对象和草稿隔离的问题。不能据此判定前端已达到正式上线或完整智能体交互的状态。

## 范围和证据

- 实际登录访客、学生、管理员三种身份，对主要页面进行 1280px 桌面与 390px 手机巡检，共 80 个页面/尺寸组合；另读取真实认领详情、匹配报告、服务站详情。
- 对搜索筛选、页面内路由切换、不同账户的草稿恢复、取消收藏失败、消息会话切换失败进行专项复现。失败请求用模拟响应，不实际删除收藏或发送消息；草稿标记仅存在于本轮独立测试浏览器中。
- 前端现有 64 项单元检查通过；生产构建通过。说明现有测试仍未覆盖本报告中的关键场景。
- 正常加载的巡检页面没有未处理脚本异常，管理员页面没有接口错误；访客读取 `/auth/me/` 的 403 是未登录会话探测，未计为缺陷。
- 两个巡检尺寸未发现整页横向溢出。未覆盖真机软键盘、所有极端标题长度、协调员专属身份、全部私有会话和交接状态，也没有穷举千问所有对话表达。
- 原始证据：`artifacts/frontend-audit/routes.json`、`interactions.json`、`findings-index.json`；截图保存在同目录。
- 本轮审查没有修复业务代码。新增巡检脚本仅用于记录证据。

## P1：先修复的四项

### F01 搜索选择类别或地点后失败〔已复现类别筛选〕

位置：[SearchView.vue](../frontend/src/views/public/SearchView.vue:14)。

选择类别后点击“搜索公开线索”，页面显示“搜索失败”。`select` 的选项绑定数值 ID，而请求拼接对所有值调用 `value.trim()`，数值没有这个方法；地点使用相同写法。

建议：统一把筛选值转换为字符串，补充类别、地点、组合筛选测试，并将筛选条件同步到地址，支持刷新和返回恢复。

### F02 地址变化但物品内容或发布类型没有更新〔已复现〕

位置：[ItemDetailView.vue](../frontend/src/views/public/ItemDetailView.vue:24)、[PublishView.vue](../frontend/src/views/user/PublishView.vue:47)。

在当前页面内从物品 A 切到 B，地址为 B，但标题仍显示 A。另从 `/publish/found` 切到 `/publish/lost` 后，地址已是寻物发布，页面仍显示“登记拾获物品”。

原因：多个页面只在 `onMounted` 读取数据；发布页面的 `activeKind`、`savedItemId` 仅在创建组件时初始化。相同组件复用时没有重置。编辑编号残留还有误改上一条记录的风险，此风险由代码确认，本轮未实际提交修改。站点详情、认领详情、匹配报告和对比页也需同类检查。

建议：按路由参数监听并重载，或为需要隔离的路由实例设置正确的 key；类型、编辑编号、照片、表单、错误和请求状态一起重置。

### F03 本地草稿没有按账户隔离〔已复现〕

位置：[PublishView.vue](../frontend/src/views/user/PublishView.vue:69)、[auth.ts](../frontend/src/stores/auth.ts)。

学生账号填写临时草稿，退出并换管理员账号后，发布页自动恢复学生账号的草稿标题。当前键只包括校区和 LOST/FOUND，没有用户编号。影响同一浏览器中的不同账户，不是服务器跨账户读取。

建议：草稿按用户、校区、类型分开保存；对旧格式草稿提供明确迁移策略。退出登录时清理当前页面内存状态。

### F04 会话切换失败后仍显示旧会话和发送框〔已复现〕

位置：[MessagesView.vue](../frontend/src/views/user/MessagesView.vue:12)。

先打开会话 11，再切换到模拟无权限的会话 12：地址为 12，内容仍是 11，没有错误提示，发送框仍在。发送函数使用旧 `current.id`，所以用户可能把原本打算发给新会话的内容发送到旧会话。

原因：参数监听直接调用没有错误处理的 `loadDetail`，切换前未清空 `current`，也没有处理先后返回的请求。

建议：切换立即进入加载状态并停止旧会话发送；新请求失败显示错误；用请求编号或取消机制避免旧响应覆盖新会话。

## P2：功能完整性与使用体验

| 编号 | 发现与证据 | 建议 |
| --- | --- | --- |
| F05 | **搜索没有翻页入口。** 实际接口返回总数 242、每页 20，页面只显示 20 条且无下一页。多个个人列表、匹配源列表、站点物品和后台列表也只读取第一页，部分用数组长度当总数。 | 使用服务端总数和分页；筛选在全量数据范围执行。 |
| F06 | **部分操作失败没有页面反馈。** 模拟取消收藏返回 500 后，页面无错误提示，出现未处理异常。订阅启停和通知已读操作也缺少统一捕获及等待状态〔后两项为代码确认〕。 | 统一错误处理、明确重试、禁止重复点击；不要只抛出异常。 |
| F07 | **小寻收到的照片不会随发布附加。** 照片上传只进入 `/assistant/image/`，核对后只保留文字观察；发布工具没有照片队列或媒体附加步骤〔代码确认〕。 | 把照片识别和照片附件分开管理；确认后将用户照片上传到实际发布记录，显示缩略图和移除入口。 |
| F08 | **小寻的认领办理只接通申请人侧。** `loadClaims` 过滤 `viewer_role==='CLAIMANT'`，没有拾得者审核通过、驳回、要求补充的操作面板〔代码确认〕。 | 按失主、拾得者、服务站角色显示各自待办；由应用权限判断可执行动作，保留必要确认。 |
| F09 | **等待声音生成时不能打字发送。** `voiceLoading` 同时禁用输入和发送〔代码确认〕。语音生成较慢时，用户必须先关闭声音才能继续文字交流。 | 语音异步准备，文字交互保持可用；新消息到来时取消或替换旧语音。 |
| F10 | **三个 AI 入口体验不一致。** 首页有小寻聊天；主导航“AI 寻物”进入的是另一套提取字段、确认、检索页面，没有小寻入口。该页桌面初始状态右侧大面积为空〔页面观察〕。 | 统一以小寻或同一工作流作为主入口；表单作为辅助编辑方式，避免用户需要重新理解流程。 |
| F11 | **管理端导航不完整。** 总览只列出 5 个模块，用户管理、报表、实验室、内容等已有路由没有统一导航入口；页面仍使用学生端顶部导航〔页面和代码确认〕。 | 建立按角色展示的管理导航，常驻入口、当前位置和返回路径一致。 |
| F12 | **内容审核材料不足，驳回原因无效。** 审核队列只展示标题、类别、地点、状态，未展示完整描述和照片，也没有查看材料入口；通过和驳回都提交固定说明“通过运营工作台处理”〔页面和代码确认，未执行审核〕。 | 增加审核详情或抽屉；驳回填写具体原因，并在用户发布记录中显示。 |
| F13 | **参考照片容易被当成该失物实拍，首页仍缺少图片。** 新增图属于同类摄影参考，具体品牌/款式可能不同；说明在详情和 AI 数据中，广场卡片未展示。手机首页四条新线索中三条使用占位图〔截图观察〕。 | 演示数据在列表提供简洁且准确的图片类型标识；补充与描述更一致的照片，优化首页图片呈现。不要给真实用户记录自动生成替代图。 |
| F14 | **用户语言和业务规则没有统一。** 广场/详情显示 OPEN、APPROVED，个人中心显示 USER、ACTIVE；订阅直接输出条件对象；个人中心仍称交接“必须在服务站”，与已支持的直接交接冲突〔页面和代码确认〕。 | 共用中文状态映射；将条件对象变成自然语言；按实际交接方式展示规则。 |
| F15 | **后台“PASS”是写死的文字。** 总览固定宣称 G02/G05/G07 PASS、页面已遍历，与运行状态和最新检查没有连接〔代码确认〕。 | 普通运营页移除工程验收文案；如需保留诊断，显示真实检查时间、版本和结果。 |
| F16 | **手机小字与表单可访问性仍不足。** 手机校区按钮为 9px，多个提示、元数据和动作是 10–12px；AI 页和发布页可见文件输入缺少可访问名称。三层全局样式和组件样式叠加，使字体、留白、按钮及表单观感不一致〔截图、样式和控件巡检确认〕。 | 统一文字层级和组件样式，减少说明段落；必要说明靠近相关操作；补齐文件输入名称、键盘状态与加载/失败反馈。 |

## 建议实施顺序

1. 修复 F01–F04，并为“筛选、同组件路由切换、换账号恢复草稿、会话失败”加入回归验证。
2. 补齐分页、失败反馈、审核材料和后台导航，保证记录找得到、操作有结果。
3. 统一 AI 入口，接通照片附件和拾得者待办，解除语音对文字输入的阻塞。
4. 再统一视觉组件、中文状态、演示配图、手机文字和页面留白。

本报告把正常加载、代码确认的功能缺口和实际复现的错误分开记录；未将通过单元测试等同于所有交互已经正确。
