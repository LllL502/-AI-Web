# 小寻会话规划与上下文记忆

日期：2026-11-16。

## 问题与改动

此前 `converse()` 的自然对话回复会被 `run_search()` 的固定检索播报覆盖，每次补充都触发搜索，用户说“不知道在哪丢的”也无法改变下一步。新的对话流程保留自然回复，通过独立的意图决定是否追问、搜索、准备草稿、查看/排除候选或继续已有认领。

- 本地模型直接接收真实 user/assistant 对话角色，不再把整段聊天作为一条待提取 JSON 文本。要求以小寻身份回答，不冒充用户复述丢失经过。
- `intent` 控制下一步，`facts_changed` 区分事实补充与普通咨询。咨询功能和请求搜索不会因为继承上一轮的搜索意图而误触发工具；搜索数量由真实检索结果补充。
- 对“不知道”“记不清”保留不可用字段记忆，不强迫猜地点、时间或外观。用户明确请求直接查找时，使用已有线索继续。
- 会话上下文使用服务端签名，绑定账号、校区，有效期一小时，不在数据库保存完整聊天。候选只记 ID，每次回应重新验证其公开状态，过期或关闭的候选不继续展示。
- 前端保留完整可见对话，请求只携带最近的问答和签名记忆；不再因为七轮对话就要求重新开始。新一轮会清理当前界面的草稿、候选和办理上下文，不会取消实际申请。
- 发布意图只打开草稿核对界面，选择候选只展开实际候选。办理结果进入聊天；真正发布、认领和交接仍调用已有权限校验、确认和幂等工具。
- 当前认领、已发布物品的状态由服务端按账号和校区验证后供对话使用。不给普通对话模型传递私密核验正文、完整学号、密码或交接码。
- 对话请求独立限额默认每分钟 20 次，语音与重推理使用原有限额；仍共用一个全局模型并发位，避免连续聊天和声音互相挤占每分钟的计数。

## 真实对话验证

使用实际本地 Qwen3-VL，依次发送：

1. 我昨天丢失了我的学生卡。
2. 我不知道在哪里丢的。
3. 卡套的颜色我也不记得了，就是普通学校学生卡。
4. 那先按我记得的信息帮我找找吧。
5. 我有点着急，你能帮我做什么？没有照片也可以发布吗？
6. 那帮我整理一份寻物启事吧。

确认了：第二轮回应“没关系，地点先留空”，保留学生卡线索；能够按已有信息真实搜索；第五轮正常解答而不重复查询；第六轮打开核对草稿。测试没有向演示库发布记录。

记录：`artifacts/xun-dialogue-real-audit.json`；页面：`artifacts/xun-dialogue-real.png`。这是一组真实功能场景验证，不是语言理解准确率或“任意说法均可理解”的证明。
