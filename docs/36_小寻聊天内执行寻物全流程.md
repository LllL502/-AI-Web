# 小寻聊天内执行寻物流程

后续已完成全链路核验，补齐照片确认直达检索、服务站交接码核验和本人确认，声音及低频动作亦已调整，最新证据与能力边界见`docs/37_小寻流程核验与声音动作调整.md`。

2026年11月16日，根据参赛者对“只整理文字、重复确认、还要跳转表单”的反馈升级。本文取代文档35中“跳转原AI页面完成检索”的流程说明。

## 能完成什么

小寻接收文字后，调用本地模型整理线索，再自动提取字段、检索当前校区公开记录，直接在聊天里展示真实物品卡片。无需额外点击结构化提取或跳回工作台确认才开始只读搜索。物品归属仍需用户核对。

用户可在聊天内查看照片与详情、排除候选，选中后继续办理：

- 发布遗失或招领信息：已知信息自动准备，缺少的类别、地点、时间由用户确认；提交后沿用原内容审核规则。
- 发起认领：关联当前用户同类别已审核遗失信息，私密特征独立输入，明确确认后提交。没有关联信息时可在同一聊天里先发布再继续。
- 查看真实审核状态、补充NEEDS_INFO材料、读取并明确发送站内沟通消息。
- 认领通过后选择直接交接或预约服务站；用户声明拿到实物后，可记录自己一方的交接确认。另一方或工作人员仍须按实际权限完成其步骤，智能体不能替其批准或伪造实物交接。
- 通过“继续已有认领”读取本人记录，恢复待办，不依赖保存上一轮原始聊天。
- 在聊天中上传照片，核对视觉观察后继续检索。默认不录音；语音继续提供点击朗读。

“看看第一个”“帮我发布寻物信息”“查看进度”“确认提交认领”等已有对话意图会调度对应操作。“核验特征：……”单独记为私密工具输入，不传入后续通用模型上下文或公开物品描述。其他自由描述仍由本地模型整理；不是任意自然语言命令都能可靠识别。

## 后端与确认

`/assistant/conversation/`在现有管理预算内执行整理、提取与检索，并返回实际工具轨迹、候选、可用元数据和已审核的本人遗失记录。模型先前的“对”“对哦”等简单肯定词不会进入物品描述，回复不再用反复“对吗”代替实际查询。

`/assistant/agent/actions/`只允许publish、claim、status、supplement、start_handover、confirm_handover、schedule。写操作必须携带明确确认和UUID操作标识，调用现有业务服务，重新验证用户、校区、状态及所有权。新增`AgentActionReceipt`唯一记录，事务内完成写入及回执；同标识重复提交返回原办理结果，不重复发布或认领。私密核验材料不复制到回执结果。补充证明沿用ClaimEvent和审计，从NEEDS_INFO回到SUBMITTED，不自行批准。

模型不直接执行数据库SQL、不指定任意工具、不绕过审核。图片观察先核对，真实发布及认领提交仍需确认，均在聊天窗口完成。消息发送仅在点击“确认发送给对方”后执行，不自动替用户联系他人。

## 验证与边界

- 后端完整回归138项通过（85.73秒）；随后增加补充核验材料能力并再次验证22项工作流测试全部通过。
- 前端49项单元测试及正式构建通过；测试覆盖聊天指令选物品、私密核验材料、明确确认提交、缺少时间时不擅自发布。
- 实际本地模型浏览器用例通过：两轮耳机描述自动查库、候选在聊天内展示和核对，全程保留/home路由；粉色A4本子描述与“对哦”后继续检索，不重复确认、不将肯定词作为特征。两条真实模型场景加桌面/手机角色与对话检查共4项通过（42.1秒）。
- 发布、防重复、认领、补充证明、本人交接确认及对方确认后完成状态由测试数据库中的真实业务服务验证；未向真实用户发送测试消息，也未在演示业务库制造测试认领。
