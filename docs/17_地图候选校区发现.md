# 顶部选择器：地图候选校区发现

2026-10-10 权威目录规则：学校只要存在至少一条 VERIFIED 校区，公开目录与地图刷新响应就只返回 VERIFIED 校区。高德新发现项仍可作为 UNVERIFIED 内部候选保存，但不进入用户下拉框，不覆盖、删除或改名正式校区。只有完全没有 VERIFIED 目录的学校，才使用地图候选/主校区解决可选性。西安交通大学因此只展示数据库内的兴庆、雁塔、曲江和中国西部科技创新港四条正式记录。

2026-10-10 手动更新：所有真实学校都提供「刷新校区」，已核实学校不会在选中时自动查询，但允许手动发起 SDK 查询并携带 refresh=true 消费新响应，绕过一天的自动发现缓存。只增加新候选，既有已核实同名校区的状态和来源不覆盖，旧校区及其物品不删除或迁移。演示学校不提供地图刷新。

2026-10-10 展示调整：核实状态和来源仅保留在数据层，选择器与地图不展示待核实/待确认说明。具体校区达到两个时隐藏未核实占位主校区；只有一个地图候选时仍只显示占位主校区。已有官网核实目录保留其真实名称，不降级为占位。隐藏不是删除，既有物品不迁移。此前说明中的前台状态提示已被本段取代。

更新：搜索改由浏览器高德 JS SDK PlaceSearch 发起（最多两页）。同源代理保留 SDK 的平台参数，短期缓存完整校名的真实上游 POI；发现接口按学校 ID 消费缓存、筛选入库。不接受浏览器提交的校区名称，不再使用 JS Key 直接发起 Web服务查询。多进程部署须配置共享缓存，否则搜索与入库可能落在不同进程而无法读取结果。

2026-10-09：对所有真实学校采用统一逻辑，而不是只为成都医学院硬编码。

选择无校区或含 UNVERIFIED 校区的学校时，顶部选择器请求 `POST /api/v1/maps/discover-campuses/`，请求体为学校数据库 ID。后端使用完整校名查高德，最多两页 40 个 POI，只接收名称以完整校名开头、剩余名称为独立「某某校区」的候选，排除附属医院、地铁站、校门等，按学校和校区名称去重。查询成功缓存一天。

候选入库为 UNVERIFIED，来源记录高德 POI 链接，不冒充官网核实。已有同名校区不覆盖。旧主校区不删除、不停用，其物品也不自动迁移。候选有稳定数据库 ID，用户确认切换后顶部、地图及 API 的 X-Campus-ID 同步使用该 ID。地图来源校区可以建立公共区域用于发布，但不能据此推断建筑或校园边界。

需要有效高德配置与可用查询权限。功能覆盖所有学校的查询流程，不代表全国所有校区已发现或核实：POI 缺失、简称、历史名称、分页上限和非「校区」命名仍可能漏检。无结果时保留占位，支持用户反馈和管理员核实补录。不批量扫描全部学校，以免超额调用；按用户选择按需发现。

联调风险：模拟测试验证筛选与存储，不验证真实 Key 的服务权限；若服务拒绝请求，页面保留原校区并提示重试。缓存为当前 Django 缓存后端，不应被当成永久资料核实证据。

前端协作提醒：此前发出的前端压缩包不包含此改动。回迁时必须保留 CampusPicker.vue 新增的发现接口逻辑，不能整目录覆盖。
