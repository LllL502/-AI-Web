# 给前端同学：AI任务接口增量

现有页面可继续使用原请求体；后端已兼容，不需要把设计预览接口替换成正式接口。此说明补充原前端交接包，不修改其基线。

## 发送一次AI操作

对prepare/search/image的每次新动作生成随机Idempotency-Key请求头。同一动作发生网络重试时保留原Key；用户改了内容或开始下一次操作时换新Key。请求原本的Cookie、CSRF和X-Campus-ID保持不变。

成功data增加workflow_id和status_url。错误可能增加error.workflow_id；这是错误元数据，不是字段错误。ApiError可新增可选workflowId属性以保留此值，不要将它渲染成错误文案。429读取Retry-After并显示简洁的稍后重试状态；409表示已处理/正在处理/请求标识冲突；504表示预算超时。

## 处理中的取消

1. 原请求尚在等待时，用GET /api/v1/assistant/jobs/?action=/api/v1/assistant/prepare/查询（action按实际接口替换），携带原Idempotency-Key和X-Campus-ID。
2. 接收workflow_id后，POST /api/v1/assistant/jobs/{workflow_id}/请求取消，带正常CSRF。若查询404，可能尚未准入，可以短暂退避再查询，不要显示已取消成功。
3. 再中止原浏览器请求；必要时查询任务状态。cancel_requested=true应显示“已请求取消”，终态CANCELLED才显示“已取消”。后台单次推理不保证立即停止。

任务状态RUNNING、SUCCEEDED、FAILED、CANCELLED、TIMED_OUT。不同用户或不同校区不能查询/取消任务。

## 模型不可用

GET /api/v1/assistant/health/返回models中vision/embedding/extraction的state与ready。capabilities.configured只说明配置已填；不能据此显示模型在线。15秒内无需频繁刷新健康接口。available表示模型已注册，并不是精度或GPU可用性的承诺。

用户界面保持简洁：只在需要时展示“当前繁忙”“服务暂不可用”“已请求取消”等状态，不必常驻展示任务编号、限流规则或模型诊断字段。

search不重放旧候选结果，防止物品撤回后泄露旧公开记录。查询结果刷新或检索重试使用新Key；所有候选以最新服务端返回为准。

持久索引版本新增503/ai_index_pending：大量记录未建索引时暂不可检索。显示服务端简洁提示即可，不要自动无限重试；后端管理员预建完成后，以新Key重试。不是前端参数错误，不需要绕过校区或审核过滤。
