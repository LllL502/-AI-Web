# 小寻：角色与寻物对话

后续已升级为聊天内直接执行检索、发布、认领与交接待办，原来的“跳转工作台继续”已被替换，最新流程见`docs/36_小寻聊天内执行寻物全流程.md`。

2026年11月16日接入。名称按参赛者要求统一为“小寻”。不再展示额外介绍卡片，完整角色独立站在首页AI寻物工作台的右上边框上。角色采用圆润短身、短脚造型，提供挥手、晃动、转圈、眨眼及单眼wink。初次气泡9秒后隐藏，此后每55秒最多显示7秒；聊天打开或页面隐藏时不弹气泡。系统减少动态效果设置会停用角色动作和后续主动气泡。

## 实际流程

点击角色打开聊天框 → 登录后描述物品 → 本地Qwen3-VL模型追问和整理 → 自动填入首页工作台 → 点击“核对描述并继续寻物” → 原AI页面提取字段 → 用户确认 → 从当前校区公开记录检索候选。

聊天不会自动发布物品、申请认领或办理交接，也不会把模型对话当作检索结果。语音为用户点击后朗读回复，未开启自动播放或麦克风录音。

## 线索来源及可靠性

新增认证接口`POST /api/v1/assistant/conversation/`。模型仅选择仍有效的用户完整原话作为证据；服务端核对原话与用户消息完全一致，再拼接为可供既有提取模型处理的描述。保留“不确定”“可能”“没有”等限定，不采用助手自行猜测的品牌、颜色等信息。

真实联调发现模型会把消息序号按“用户轮数”计数。现在仅在完整引文确实对应另一条用户消息时纠正编号；无真实原话支持的内容仍拒绝。该策略不等同于证明模型能完美识别所有更正与否定，检索前的人为确认步骤继续保留。

推理期间工作台被手动编辑时，不自动覆盖，改为提供“填入工作台”。失败时恢复输入并保留此前对话。对话上限16条输入消息、总计8000字，工作台描述上限1200字；较长对话可使用“新一轮”。聊天仅在当前页面内存中保留，刷新、切换校区、离开首页或更换登录账户后清除。

## 任务及隐私

聊天复用全局并发、用户频率、90秒任务预算和幂等请求保护，接口不处于长数据库事务中。客户端80秒停止等待，支持显式停止并向任务取消接口发起协作取消；这不代表瞬间停止GPU推理。与检索一样，不在AIJob中留存聊天响应，也不重放结果。模型请求与回复作现有最小联系方式脱敏，界面按纯文本展示。

## 验证

- 后端完整回归134项通过（96.01秒）。修复消息编号问题后，7项对话专项测试通过，包括不确定性保留、脱敏、禁止模型虚构引文、禁止引用助手猜测及编号修正。
- 前端47项单元测试通过，包含自动填写、保护推理期间的人工编辑、访客禁止推理；正式构建通过。
- 新版角色及聊天框在390px和1440px浏览器验收通过，无水平溢出，支持Escape关闭及焦点返回。
- 真实本地模型两轮聊天、补充线索自动填写、跳转确认和真实候选检索整条用例通过（11.1秒）。这是一条真实模型联调案例，不是泛化准确率评测。
