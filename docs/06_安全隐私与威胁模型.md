# 06 安全、隐私与威胁模型

## 1. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 越权查看他人物品/认领 | Django 对象查询范围、站点成员关系、字段级序列化、403/404 防枚举 |
| CSRF 与会话窃取 | SessionAuthentication、CSRF token、HttpOnly、SameSite=Lax、登录轮换会话 |
| 公开描述泄露联系方式 | 发布提示、内容审核、精确地点和敏感字段不进入公开序列化器 |
| 虚假认领 | 私密举证、人工决定、唯一保留、站点线下核验 |
| 交接码暴力尝试 | 只存密码摘要、有效期、最多 5 次、重新预约、双方确认 |
| 并发批准两个认领 | `transaction.atomic`、`select_for_update`、`ActiveReservation` 一对一唯一约束 |
| 算法高分被当成归属证明 | 所有解释使用“候选/核查”措辞，高分不能自动批准认领或归还 |
| 管理操作不可追责 | `AuditLog` 保存操作者、对象、动作、前后摘要和 request_id |
| 长任务刷新后丢失 | `PersistentTask` 入库保存状态/进度/错误，不使用内存定时器假进度 |
| 公网撞库与演示账号泄露 | 登录/注册限流；公网进程拒绝所有文档中公开的固定演示账号；注册只能获得 USER 角色 |

## 2. 部署边界

本地演示服务器仅监听 `127.0.0.1`：Vue `5173`、Django `8000`、MySQL `3307`。公网测试模式另启 Waitress `8010` 与 Vite Preview `4173`，仍只监听 `127.0.0.1`，由 Cloudflare Tunnel 建立出站连接并提供随机 HTTPS 地址；不开放路由器入站端口，也不创建 Windows 服务。MySQL 二进制、数据和日志均位于 `campustrace/` 内。

公网测试模式启用 Secure Session/CSRF Cookie、`https://*.trycloudflare.com` CSRF 来源白名单和生产前端构建。Quick Tunnel 仅用于测试：链接随机、依赖本机持续在线、没有固定 SLA；正式部署应改用固定域名、受管隧道或独立服务器，并更换所有密钥与演示凭据。

## 3. 日志规则

日志可包含 request_id、用户 ID、对象 ID、稳定错误码和耗时；不得记录密码、Session cookie、CSRF token、交接码原文、私密答案、完整联系方式或原始证件号。
