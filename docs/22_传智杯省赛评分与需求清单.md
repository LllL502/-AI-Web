## 1. 参赛定位与产品边界

- 作品名：**寻迹——校园多模态智能寻物助手**。
- 赛道类别：**第 10 类“AI 社交与社区应用”**。
- 核心链路：模糊文字/物品照片 → 结构化提取并由用户确认 → 必要时动态补问 → 权限和校区过滤 → 真实物品语义/图片辅助召回 → 六因子证据排序 → 引用真实候选解释 → 现有人工认领与交接。
- 安全红线：模型不能批准认领、删除线索或完成交接；不向公开检索泄露私密特征；不虚构候选、引用或匹配原因；匹配分是检索排序证据，不是物品归属概率。
- 当前阶段只做本地开发与验证，不启动云端服务、不上线、不产生付费调用。

## 4. 评测和可追溯性

- 已有基线：TF-IDF + 六因子、候选约束、分项证据和合成评测脚本。
- 旧的 80 查询/320 候选是构造数据；旧 Top-1 76.25% 只能说明该构造评测上的排序结果，不是校园实际找回率。
- 待补统一实验：旧六因子、语义检索、图片辅助召回，共用同一候选过滤和数据划分。
- 必报指标：结构化提取字段正确率/完整率、Recall@K、MRR/Top-K（如适用）、候选过滤正确性、端到端延迟、失败率、单次调用成本。
- 必保留：失败案例、空候选、图片不可用、模型超时、结构化输出非法、模型提供方不可用等记录。
